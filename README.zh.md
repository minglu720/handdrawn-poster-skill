# 手绘编辑海报 Skill
[English](./README.md) | [简体中文](./README.zh.md)

**将主题、文字、物件或照片，转化成线条松弛、排版鲜明、具有纸张触感的原创海报。**

`Hand-Drawn Editorial Poster Skill` · 视觉研究初版 v0.1

</div>

这不是一个固定的“店面线稿模板”，也不是把任何照片直接套上铅笔滤镜。这个 Skill 从 **7 张参考海报**中提取可重复使用的视觉语法：有意保留的手绘痕迹、选择性描绘、字体层次、纸面留白与克制的印刷质感。面对不同的主题，它会重新选择主体、构图、字体表达和配色，而不是复刻某张参考图。

> **当前状态：** 这是可供实验的 v0.1 规则说明，不是训练完成的图像模型。是否能直接生成图片，取决于运行它的 AI 环境是否提供图像生成能力。以下参数是设计起点，不是对七张参考作品的精确测量。

## 它能做什么

| 维度 | 设计能力 |
|---|---|
| **输入** | 主题、短句、活动文案、建筑或店面照片、食品、物件、抽象概念 |
| **绘画** | 不完全平滑的手绘线条、重复描线、适度粗细变化、选择性结构细节 |
| **主体** | 可识别的建筑立面、独立物件、食品、视觉隐喻；不限定为店面 |
| **字体** | 手写大字、自由书写体、连笔标题；与清晰可读的正文或活动信息搭配 |
| **配色** | 默认一色油墨加纸色；可根据要求改为深底反白或少量强调色 |
| **纸张** | 可见底色、轻微颗粒、适量印刷不均匀感；不自动重度做旧 |
| **构图** | 依据主体与文案在不同版式之间做选择，而不是固定一个网格 |
| **输出** | 在支持的环境中生成海报；或只输出生产级 Prompt 和视觉配方 |

## 核心视觉规则

**01 · Human line / 人手感线条**  
保留轻微抖动、断笔、重描与压力变化。线条可以松弛，但建筑的入口、门窗、物体的关键轮廓仍须清楚可辨。避免机械一致的矢量描边。

**02 · Selective representation / 选择性描绘**  
不是完整临摹照片。建筑优先保留轮廓、入口、窗户、遮阳篷等识别锚点；食物和物件可以进一步符号化。不要把所有主体都画成店铺。

**03 · Expressive type / 有表达力的字体层级**  
主标题可以大幅手写、字距不匀、具有个性；日期、时间、地址和说明仍需可读。并不强制某一种现成字体或完全相同的手写笔迹。

**04 · Paper-led composition / 以纸面组织构图**  
把留白视为正式设计元素。纸张纹理支持线条，而不是盖过信息；不默认加入泛黄、污渍、撕边等怀旧装饰。

## 可调整的设计参数

| 参数 | v0.1 默认建议 | 什么时候改变 |
|---|---|---|
| 画布比例 | 竖版 `4:5` | 用户指定印刷尺寸、社交平台或横版时 |
| 留白 | 约 `35%–60%` 开放纸面 | 文字较多、主体复杂或要求紧凑版式时 |
| 色彩 | `1` 种线条/油墨色 + 纸色 | 特定品牌色、深色纸张或需要少量强调色时 |
| 纸张材质 | 低至中等颗粒与印刷不均匀 | 用户要求更干净或更粗粝时 |
| 字体 | 表现性标题 + 易读信息文字 | 物件占主导、长文案、正式活动信息时 |
| 细节密度 | 只保留关键识别特征 | 复杂建筑增加局部细节；简单物件减少笔画 |

这里的数字是**可测试的默认值**，并非从参考图自动测出的硬性规范。

## 工作方式

```text
1. 读取需求       → 判断主题、主体、用途、确切文案与图片角色
2. 选择画法       → 建筑结构速写 / 单件物体简笔 / 具象视觉隐喻
3. 选择版式       → 标题-插画-信息 / 文字融入物件 / 符号组合 / 书写标题主导
4. 配置视觉       → 手绘笔触、字体层级、色彩、留白、纸张触感
5. 生成与检查     → 文字、主体识别度、层级、原创性、材质是否符合
```

### 条件判断（If / Then）

- **如果**输入是一张店面或建筑照片，**那么**保留可辨识的轮廓、门窗和入口，简化无关环境。
- **如果**主体是食品或日常物件，**那么**使用更经济、符号化的线条，不加入无关的建筑立面。
- **如果**主体结构复杂，**那么**减少字体装饰；**如果**图形特别简单，**那么**允许标题更大胆。
- **如果**信息量大，**那么**优先保证日期、地址和说明的可读性，只在短标题上使用表现性手写。
- **如果**使用深色背景，**那么**转为浅色线条，同时保持对比度。

## 常用版式方向

| 版式 | 适合情况 |
|---|---|
| **A · 垂直编辑层级** | 标题在上、中央插画、底部活动信息 |
| **B · 图像即招牌** | 文字自然进入门面、海报标牌或其他合适物件 |
| **C · 符号组合** | 两至三个小物件构成视觉叙事，例如时钟 + 食物 |
| **D · 书写体主导** | 大面积手写标题，搭配安静的插画和页脚信息 |

以上是可选的构图路径，不是四张必须复刻的模板。

## 如何使用

这个仓库用 Markdown 保存视觉分析与 AI 的行为指令。入口文件是 [`SKILL.md`](./SKILL.md)，但 **GitHub 本身不会运行图像生成**。

1. 在支持自定义 Skills 的 Agent 中添加本仓库或加载 `SKILL.md`。
2. 确保 Agent 能访问 `references/visual-analysis.md` 和参考图，并拥有可用的图像生成工具（如果需要直接生图）。
3. 给出主题、主体或照片、必需文案以及尺寸；未指定的视觉细节交给 Skill 按规则决定。
4. 检查生成的文字与可辨识结构。精确排版可能需要在设计软件中进一步校对。

不同 AI 环境的安装方式不相同；此版本暂不声称兼容所有 Agent，也没有自动安装脚本。

## 原创性与使用边界

- 提取的是**视觉语言**，不复制单一参考作品的构图、商标、活动信息或个性化签名。
- 用户提供照片时，保留主体的辨认特征；不需要机械地描摹所有像素。
- 不虚构品牌名称、日期、价格、活动地址、赞助商或二维码。
- 如果运行环境没有生图能力，应明确说明，并提供可执行的图像 Prompt，而非假称已生成成品。
- 参考图片包含第三方视觉作品；公开仓库不代表自动获得转载或再许可权。
